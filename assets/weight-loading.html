Weight loading: mmap → shard → GPU

What actually happens between safetensors_weights_iterator yielding a tensor and a sharded parameter landing on the GPU — and where the "pinned buffer" intuition breaks down.

Pipeline

Correction to the pinned-buffer intuition

param_data.copy_(loaded_weight) where loaded_weight is an ordinary (non-pinned) CPU tensor is a plain synchronous cudaMemcpy. PyTorch does not stage it through an internal pinned bounce buffer automatically.

The mmap'd source pages are what's paged — so the copy itself can stall on page faults as it reads, not on GPU-side staging. Pinned-memory staging only shows up where a loader path deliberately allocates and reuses a pinned tensor (some prefetch / fastsafetensors paths do this) — not on this default safetensors_weights_iterator route.
