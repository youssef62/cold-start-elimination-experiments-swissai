# Lustre weight-loading methods sweep

Two full loader-comparison sweeps for `Llama-3.1-70B-Instruct` (TP4) on Bristen,
`--cpus-per-task=128`, run back-to-back on distinct nodes per arm (fresh node
per arm, since page cache from a prior arm would contaminate the next). Six
arms per sweep: `mmap` (SGLang default), `nommap`
(`--weight-loader-disable-mmap`), `fst` (`--load-format fastsafetensors`),
`shm_mmap` (`/dev/shm` staging + mmap), `preshard` (`/dev/shm` +
TP-presharded), `overlap` (presharded + overlap staging with engine start).

- `results/methods_sweep/bristen-2026-08-24-cpu128/` — collected 2026-08-24
- `results/methods_sweep/bristen-2026-08-25-cpu128/` — collected 2026-08-25
- `results/methods_sweep/bristen-2026-08-31-cpu128/` — collected 2026-08-31

Each directory has one `servekit profile` JSON per arm and a `results.md`
(loader comparison table, per-run detail, phase breakdown) generated by
`scripts/methods_sweep/summarize_methods_sweep.py`.

The blog's Section I phase breakdown and Section II loader-comparison table
both cite the **same run** — `bristen-2026-08-24-cpu128`'s `mmap` arm
(job 80538) — so the two tables describe one consistent baseline instead of
two different days. Run-to-run variance is large: `mmap` weight_loading was
453.7s on 08-24, 857.1s on 08-25 and 402.5s on 08-31, all on otherwise-idle
capstor. The 08-25 and 08-31 sweeps give 3 runs per arm; per-phase statistics
(mean, stddev, min, max) across all three are in `results/phase_stats.md`
(generated by `scripts/analysis/phase_stats.py`) and reproduced below.

### Loader comparison

| config | weight_loading mean_s (stddev) | min-max | speedup | total mean_s (stddev) | min-max |
|---|---|---|---|---|---|
| default loader | 571.1 (249.0) | 402.5-857.1 | 1.0x | 743.2 (245.7) | 574.7-1025.1 |
| nommap | 47.2 (2.0) | 45.7-49.5 | 12.1x | 215.9 (1.2) | 214.7-217.1 |
| fastsafetensors | 67.0 (16.1) | 56.3-85.5 | 8.5x | 238.1 (15.8) | 227.9-256.3 |
| /dev/shm staging + mmap | 20.2 (0.3) | 20.1-20.6 | 28.2x | 189.6 (2.3) | 187.0-191.5 |
| /dev/shm + TP-presharded | 9.2 (0.3) | 8.8-9.4 | 62.2x | 173.9 (9.2) | 163.3-179.7 |
| /dev/shm staging + presharded + overlap | 9.5 (0.2) | 9.3-9.7 | 60.4x | 182.7 (4.4) | 178.9-187.4 |

Speedup is relative to the default loader's mean. `weight_loading` is highly
variable (capstor contention); every other phase is flat within ~1s across
runs, so `total` variance tracks `weight_loading` variance almost exactly.

## Reproducing

```
bash experiments/lustre-loading-exp/scripts/methods_sweep/methods_sweep_chain.sh
python3 experiments/lustre-loading-exp/scripts/methods_sweep/summarize_methods_sweep.py \
  experiments/lustre-loading-exp/results/methods_sweep/<new-dir>
```

`methods_sweep_chain.sh` submits all six arms one at a time (fresh node per
arm), each via its own sbatch script under `scripts/methods/`:

- `mmap.sbatch`, `nommap.sbatch`, `fastsafetensors.sbatch` — read straight off capstor
- `shm_mmap.sbatch` (+ `stage_to_shm.sh`, the within-file-fanout stager all
  shm-based arms use)
- `preshard.sbatch` — requires a presharded checkpoint from
  `save_sharded_ckpt.sbatch` (`save_sharded_state_fixed.py`) to exist first
- `overlap.sbatch` — same presharded checkpoint, staged concurrently with
  engine startup instead of before it

All arms share the SGLang container EDF at
[`examples/profile/llama-3.1-70b-bristen/llama-3.1-70b-sglang.toml`](../../examples/profile/llama-3.1-70b-bristen/llama-3.1-70b-sglang.toml),
and expect a `servekit` checkout at
`/iopsstor/scratch/cscs/yboughizane/cold-start-elimination/servekit-main`
(override with `SERVEKIT_DIR`) — see the
[Servekit repo](https://github.com/eth-easl/servekit).

`scripts/analysis/summarize_e2e.py` is the lower-level per-run summarizer
(phases, throughput, cross-run correctness) that `summarize_methods_sweep.py`
builds on.

`scripts/analysis/phase_stats.py` computes per-phase mean/stddev/min/max
across repeated runs of the same arm (`--markdown`), or a loader-comparison
table with speedup relative to the first arm (`--compare`):

```
python3 scripts/analysis/phase_stats.py --markdown <profile.json> <profile.json> ...
python3 scripts/analysis/phase_stats.py --compare "label=file1,file2,..." "label2=file1,file2,..."
```
